# Автотесты API NordCodes

Java 17+, JUnit 5, Maven. Приложение проверяется через HTTP без изменения его кода. Для внешнего сервиса используется HTTP-сервер JDK с управляемыми ответами и регистрацией запросов.

## Запуск

1. Установить JDK 17+ и Maven 3.9+.
2. Распаковать предоставленный архив и поместить `internal-0.0.1-SNAPSHOT.jar` в `sut/`.
3. Выполнить `mvn test`.

Другой путь к приложению: `mvn test -Dsut.jar=/absolute/path/app.jar`.

Тесты запускают приложение и внешний сервис на свободных локальных портах, ожидают готовность приложения и останавливают их после проверки. Методы выполняются последовательно; сценарии используют отдельные токены.

Результаты Maven: `target/surefire-reports/`. Лог приложения: `target/application.log`.

## Покрытие

- Вход, действие, выход и запрет действий без активной сессии.
- Изоляция сессий пользователей.
- Валидация токена, действия и API-ключа.
- Ошибки внешнего сервиса и отсутствие сессии после неудачного входа.
- Метод, путь, заголовки и тело исходящих запросов.
- Отсутствие внешних вызовов при локальном отказе.
- Независимость результата от тела ответа внешнего сервиса.

## Результаты и ограничения

Прогон 03.11.2026: Maven 3.9.11, JDK 24, компиляция под Java 17. Из 35 проверок прошли 33. Два падения описаны в [итоговом PDF-отчёте](docs/report.pdf): дефект алфавита токена и вопрос об обработке пробелов в action. При этих падениях `mvn test` завершается с ошибкой.

Точный текст прикладных ошибок не закреплён в задании: проверяются `result=ERROR` и непустое `message`. Для неверного API-ключа ожидается HTTP 401 или 403 — это допущение.

Нагрузка, конкурентные запросы, сетевые таймауты и неподдерживаемые HTTP-методы не проверялись. Повторный LOGIN, LOGOUT без сессии и точная граница успешных HTTP-кодов внешнего сервиса требуют уточнения требований. Запуск непосредственно на JDK 17 отдельно не проверялся.

Архив приложения, JAR и результаты сборки исключены из Git.
