# Автотесты API NordCodes

Java 17+, JUnit 5, Maven. Проверяется исходное приложение через HTTP; его код не изменяется.

## Запуск

1. Установить JDK 17+ и Maven 3.9+.
2. Распаковать выданный работодателем архив. Положить `internal-0.0.1-SNAPSHOT.jar` в `sut/` (либо указать `-Dsut.jar=/absolute/path/app.jar`). Архив и приложение не публикуются в Git.
3. Выполнить `mvn test`.

Тесты сами запускают приложение и внешний сервис на свободных портах, ожидают готовность приложения и завершают процессы после проверки. Нужны разрешённые локальные TCP-соединения. Параллельный запуск методов выключен по умолчанию: внешний сервис имеет общие настройки ответа. Каждый сценарий использует отдельный токен.

Отчёт Maven: `target/surefire-reports/`. Лог приложения: `target/application.log`.

Для этой рабочей среды также есть `pwsh -File scripts/test-local.ps1`: компиляция и запуск тех же JUnit-тестов из локального Maven-кэша без сети. Это вспомогательный скрипт для установленного здесь JDK 24, а не замена стандартной команды Maven. Он создаёт читаемый HTML `target/report.html` и возвращает ненулевой код при сбоях. Исходники компилируются с `--release 17`.

## Что проверяется

- Вход, действие, выход, запрет действия после выхода.
- Изоляция сессий двух пользователей и запрет действий до входа.
- Длина и алфавит токена, отсутствующие и пустые параметры, неизвестные действия.
- Отсутствующий, пустой и неверный API-ключ.
- Метод, путь, заголовки и тело запросов во внешний сервис; отсутствие этих запросов при локальном отказе.
- Ошибки внешнего сервиса 4xx/5xx и отсутствие сессии после неудачного входа.
- Независимость результата от тела ответа внешнего сервиса.

HTTP-код успешного прикладного ответа и точный текст ошибок в задании не закреплены: проверяются JSON `result` и непустая причина ошибки. Для отказа в доступе ожидаются общепринятые 401/403 (допущение).

Вместо WireMock используется маленький HTTP-сервер JDK, вместо Allure — стандартный отчёт JUnit/Maven и локальный HTML. Стек в задании рекомендательный; эти решения позволили реально выполнить тесты в среде без загрузки новых зависимостей. Проверяются реальные исходящие HTTP-запросы, а не подменённые Java-методы.

## Фактический результат

Локальный запуск 03.11.2026: 35 тестов, 33 успешных, 2 падения; запуск на JDK 24, компиляция под Java 17. Повторный запуск через Maven 3.9.11 подтвердил тот же результат. Запуск на JDK 17 отдельно не проверялся. Подробности: `FINDINGS.md`. Падающие проверки сохранены: менять ожидания под дефект приложения неправильно.

Не охвачены: нагрузка, одновременные запросы, сетевые таймауты, некорректный Content-Type, неподдерживаемые HTTP-методы. Повторный LOGIN, LOGOUT без сессии и точная граница успешных HTTP-кодов внешнего сервиса требуют уточнения контракта.
